# GuildRecruit735 1.0.6 / GR735-20261019-01 — проверка сканирования

Статус: сборка для игрового теста, STATIC_VERIFIED, GAME_NOT_OBSERVED. На GitHub остаётся прежний релиз1.0.4. База этой сборки — точная1.0.5 (поправки прокрутки/растягивания сохранены).

## Что изменилось

- Одна проверка пригодности для приёма WHO-строк, списка и ручного контакта. В памяти хранятся все полученные уникальные строки, включая исключённые (до5000); в SavedVariables этот снимок не записывается.
- Все принятые кандидаты доступны страницами по30; стрелки/колесо/ползунок прокручивают текущую страницу. Предел5000 не скрытый: остановка помечается неполной. Старые фильтры, история30дней, шаблоны и их ID сохраняются.
- Изменение настроек/активного фильтра останавливает старый скан и перестраивает уже полученные данные; для полного охвата нового диапазона или новых HC-данных нужен новый скан.
- Правила мира точные: x7 и plusx7 означают суффикс мираplusx7, а не часть ника. Точные старые токеныxN/plusxN в прежних правилах имени интерпретируются как мир без перезаписи сохранённых правил. Остальные подстроки имён сохраняют прежнее назначение. Новые такие токены автоматически создают правило мира; оно сначала выключено.
- HC и история контактов сопоставляют имя с суффиксом и без него только при известном совпадении текущего мира. Одноимённые игроки разных миров не объединяются. При неизвестном формате мира не угадываем соответствие. HCрежимы/уровень110/срокистории не переосмыслены.
- Статус завершения/таймаута/неполноты виден в минипанели; подробные счётчики — при наведении. `/gr735 status` выводит детали, `/gr735 why Имя-мир` объясняет исключение в полученном снимке. Отсутствие строки означает «не получен», а не доказанный офлайн.
- Весь WHOответ проверяется на соответствие текущему диапазону и классу до изменения снимка. Несоответствие прекращает скан с предупреждением. API не даёт requestID: одинаковый по диапазону чужой ответ всё ещё нельзя криптографически связать с запросом.
- Пассивный `hooksecurefunc` наSendWho обнаруживает другой ручной/аддонный запрос и останавливает наш скан; функция не заменяется, запросы других аддонов не блокируются. Если hooksecurefunc недоступен, остаётся проверка ответа, но защита от смешивания слабее.
- Переполненный уровень дополнительно делится по12классам, только если клиент предоставляет WHO_TAG_CLASS и полный список локализованных названий. Если сервер игнорирует класс, скан останавливается явно; если класс тоже переполнен, отмечается неполнота. Интервал8с, таймаут45с и максимум120запросов сохранены.

## Установка

При закрытой игре заменить папкуGuildRecruit735 из установочногоZIP. WTF/SavedVariables не удалять; не сбрасывать историю/HCкэш для «чистого теста». Эта сборка не устанавливает рекламу в общий чат и не добавляет автоматических приглашений. Все контакты по-прежнему вручную.

## Целевой игровой тест

1. `/gr735 version`:1.0.6 / GR735-20261019-01. Сохранить снимок действующих настроек и активных правил, в том числе старогоx7.
2. Запустить привычный диапазон10–110/HCexclude. Дождаться явного завершения или причины остановки; сохранить `/gr735 status`. При большом онлайне процесс может занять много запросов, не обещать полный охват.
3. Если найдено более30кандидатов — кнопками страниц добраться до31-го и последнего; проверить обратный переход, прокрутку/растягивание и ручной выбор именно показанного игрока. Для проверки UI не нужно отправлять приглашения всем подряд.
4. Включить/выключить правило/исключённый класс после поиска: список должен перестроиться. При изменении во время скана он должен остановиться с указанием перезапуска. Выключение фильтра возвращает только уже полученных игроков.
5. Правилоx7: plusx7исключён, plusx1сx7всамомнике не исключён этим правилом. Обычное правило имени по-прежнему ищет подстроку. Статусы правил показаны отдельно от их общей доступности.
6. `/gr735 why Имя-мир` — сравнить объяснение с HC/классом/правилом/гильдией/контактами/уровнем. Если игрок отсутствует, остановить скан и проверить штатныйWHOпоимени до приглашения вгильдию. Не смешивать ручнойWHOсактивнымсканом.
7. Для HC-формата проверить реального известногоHCссуффиксом и без него; не использовать игрока другого мира как положительное подтверждение. Без подходящего примера этот пункт NOT_OBSERVED.
8. Открыть ручнойWHOво время скана: при доступном securehook нашскан останавливается, штатныйWHOработает. Таймаут/неполнота не должны выглядеть как успешный полный поиск.

Сохранить build, скриншоты статуса/правил/страниц, точные имена ещё не вступивших кандидатов и BugGrabber при ошибке. Сейчас точная причина двух старых пропусков UNVERIFIED. Новую сборку нельзя объявить GAME_VERIFIED только по офлайн-проверкам. ПланируемыйID GAME_TEST_009 — перед записью сверить свежий handoff, номер мог быть занят позднее.

## Откат и ограничения

Старая1.0.5/стабильная1.0.4 не перезаписаны. Откат заменой папки при закрытой игре, с сохранениемWTF. Новые правиламира имеют уже поддерживаемый старымформатом kind=realm; старые сборки трактуют его как подстроку, поэтому откат возвращает прежнюю семантику.

Успешныйpcall не доказывает доставку whisper/invite. Срокконтактов30дней остаётся от попытки. КэшHCне получает новогоTTL, получение двух частей не доказывает абсолютную полноту глобального списка. СервернаявидимостьWHO/оффлайн/переходы/чужиеаддоны ограничивают покрытие; обещания «все игроки онлайн найдены» нет.
